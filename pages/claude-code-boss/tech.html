Daemon HTTP único ADR-001

O brain-server roda como um único daemon HTTP de longa duração (StreamableHTTP, stateful) numa porta fixa (58217), compartilhado por toda sessão do Claude Code e qualquer outro consumidor na máquina — um modelo, um SQLite. O .mcp.json usa "type":"http" direto (sem spawn por sessão).

sessão 1▸ sessão 2▸ sessão N▸ daemon único :58217▸ 1 modelo · 1 SQLite

Garantia + lifecycle

  • Auto-start + auto-upgrade: o hook brain-daemon-ensure.js (SessionStart/UserPromptSubmit) encontra-ou-inicia o daemon; a cada atualização do plugin, troca um daemon obsoleto pelo novo (lock em DATA_DIR + checagem de versão via /health). Desligue com BRAIN_HTTP_AUTOSTART=0.
  • Auto-setup em background: se o node_modules está faltando, o hook roda plugin-setup.js em background (detached, non-blocking) antes de tentar o spawn — sem bloquear a sessão e sem exigir intervenção.
  • Fail-open: qualquer erro só adia a disponibilidade da KB; o próximo SessionStart/UserPromptSubmit re-emite o ensure. Nunca bloqueia o início de sessão.
  • Endpoints: /health (aberto), /mcp (guarda de Origin), /shutdown (exige token local em <DATA_DIR>/brain-http.token ou BRAIN_HTTP_TOKEN).
  • Limites: MAX_BODY_BYTES = 1MB (proteção contra OOM), MAX_SESSIONS = 50 (prevenção de exaustão de FDs); graceful shutdown sem process.exit() hard kill.
Consumo externo: qualquer ferramenta (ex.: OpenCode) aponte para http://127.0.0.1:58217/mcp com project explícito. O parâmetro project é obrigatório por chamada — sem ele, o daemon rejeita (PROJECT_REQUIRED).

Brain KB 3 camadas

Base de conhecimento local com 3 layers:

tier 1

Storage

brain-store.js — SQLite via node:sqlite (built-in, zero deps nativas) com fallback para better-sqlite3 e, por fim, JSON. Busca vetorial (cosine similarity JS, <10K entradas) + FTS keyword.

tier 2

Index

brain-index.js — Índice invertido de palavras-chave com TF scoring.

tier 3

Graph

brain-graph.js — Grafo de citação com 6 tipos de aresta.

Config & perfis

Um único eixo de enforcement, três modos — lido do config shipped mesclado com DATA_DIR/hooks/user-config.json (update-safe, sobrevive ao auto-update).

default

standard

Silencioso, mas aprende: só a curadoria dá 1 aviso soft e relenta. correction-detect fica LIGADO (nudge silencioso). Ficam desligados os nudges interruptivos e ferramentas de dev. session-summary (1×/sessão) e o retrieval continuam.

para quem estende o plugin

dev

Tudo ligado — curadoria escala até 3×; nudges, decisões, self-review, pesquisa, retros, auto-continue.

sem enforcement

free

Passa tudo: o Stop-dispatcher faz short-circuit e nada bloqueia; só o retrieval de contexto no prompt (read-only) segue ativo.

Backends do Brain

  • local (padrão): SQLite no DATA_DIR/brain/<projeto>/brain.db — zero servidor externo.
  • mcp-memory (server-side): conecta a um mcp-memory-server (HTTP auto-discovery via ~/.mcp-memory/run/daemon.json ou stdio com Java 21+). Ingestão opt-in, desligada por padrão. Botão Migrar agora leva o acervo local para o servidor projeto a projeto (idempotente, fail-loud).
  • MCP Activation Wizard (scripts/lib/mcp-wizard.js): ativa o backend mcp-memory em 5 passos com estado persistido — Java ≥ 21, JAR presente/download, spawn do daemon, handshake MCP (initialize + tools/list), validação do projectId. Fire-and-forget com polling (POST /api/brain/mcp-wizard, GET .../status); no Dashboard vira o botão Activate Server com progresso passo-a-passo.
  • Status em tempo real (scripts/brain-status.js, hook no UserPromptSubmit e comando /brain-status): reporta mode, connected, project, backend, details (URL/transporte/JAR) e latency — mesmo contrato exposto em GET /api/brain/health e refletido no badge online/offline do Dashboard.

Identidade do projeto (recall entre máquinas/pastas)

Precedência: CCB_PROJECT_ID (env) → .claude-boss-project (arquivo na raiz do projeto, viaja com a pasta) → basename(cwd) (default legado). Escopo anti-contaminação: o daemon filtra por project_id no handshake.

Graph tools 7 tools

Exploração rápida de repositório via Session Graph Engine (cliente REST puro, nenhum Java embarcado). Hubs por PageRank, busca semântica com vizinhança (CALLS/CONTAINS/IMPORTS), quem-chama-um-símbolo — para entender um repo grande sem garimpar arquivo por arquivo.

ToolO que faz
graph_analyzePorta de entrada: ensureReady + hubs + busca opcional
graph_searchBusca semântica com expansão de vizinhança (N-hops)
graph_symbolsLista hubs por PageRank ou busca por nome
graph_statusNodes, edges, hubs — read-only, não indexa
graph_ingest / graph_reindexIndexa o projeto (async, poll até ready)
graph_callersQuem chama um nó (inbound CALLS edges)
graph_referencesTodas as referências a um nó (CALLS + CONTAINS + IMPORTS)
graph_tag_nodeMarca um nó com termos extraídos
Fail-open: se o daemon de memória estiver offline, as tools graph_* falham graciosamente — nunca derrubam a sessão. Independentes do KB local/mutex.
