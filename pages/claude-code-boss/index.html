Novo na 3.0: a curadoria fecha o ciclo, e presta contas

Seis recursos novos: o dashboard abre sem gastar um turno, o script curado se estende, se ajusta e é podado quando ninguém o usa, e a sessão começa dizendo o que a curadoria rendeu. Cada um foi provado no Claude Code real.

variante → alias

Variante recorrente estende o script curado

1 linhaem vez de 404, na sessão seguinte

Quando uma variante de um comando curado (ex.: npm test -- --reporter=dot com o script cobrindo npm test) roda crua, ruidosa e se repete, o Stop não pede um segundo script: pede para estender o existente (EXTEND) e registrar a variante como alias. Daí em diante ela é redirecionada, e o registro preserva os ajustes do script (orçamento, timeout, label, ícone).

O filtro vai para a origem, não para cada chamada

Se o agente filtra a saída de um script curado sempre do mesmo jeito (node tests.mjs | tail -3), o Stop pede uma vez para embutir o filtro no script ou no seu outputLines. Depois a decisão é do agente: se ele explica por que o filtro fica, o boss não insiste.

BRAIN-HEALTH · hook lento

Aviso antes de um hook ficar sem folga

p95 ≥ ½ prazocom 10+ chamadas medidas, ou algum prazo estourado

O sinal vem antes de o hook começar a não decidir nada (fail-open). No máximo uma vez por hook a cada 6 h por processo do daemon, e só sobre o daemon desta instalação.

3.0.0: a curadoria redesenhada, e o que muda para você

Uma versão major. Ela inclui tudo o que estava preparado como 2.29.1 (nunca publicada), o redesenho da curadoria, o endurecimento do daemon de hooks e as correções de escopo por sessão.

incompatível · U4

Composto identificado por todos os segmentos

Um comando composto passa a ser identificado por todos os seus segmentos de trabalho, em ordem: git status && git diff ≠ git status. Antes, 425 assinaturas cobriam 2.285 comandos diferentes; agora são 27.

incompatível · U13

Número de descritor fora da assinatura

git status 2>&1 passa a ser git status: o 2 colado ao redirecionamento sai, mas sleep 2 > f mantém o 2.

incompatível · curadoria

Redirecionar em vez de negar

O guard não nega mais variantes nem pipes: reescreve comandos de tarefa para o script curado e só pede script para comando de tarefa que se repete.

incompatível · hooks no daemon

13 hooks rodam como mcp_tool

Os 12 da Fase G mais o hook_policy_inject do SubagentStart rodam no brain-server, que precisa estar conectado. Com ele fora do ar, o Claude Code trata o hook como erro não bloqueante. Na 1ª sessão depois de boot, update ou reload, os hooks dos primeiros segundos podem ser pulados enquanto o cliente reconecta.

incompatível · permissões

O boss não aprova mais comandos por você

O curation-guard e o graph-guard respondiam allow como padrão "nada a fazer" para todo comando Bash/Grep/Glob, e um allow de PreToolUse pula o sistema de permissões do Claude Code: quem não usa bypassPermissions tinha tudo aprovado sem prompt (vinha da 1.x; achado pela auditoria pré-release). Agora "nada a fazer" é abstenção ({}) e o seu fluxo de permissões decide. Só as reescritas decidem: o redirect (allow em bypass, ask nos demais modos) e o moldador (só em bypass). A whitelist do shells.json passa a só isentar do modo denyUnknown.

Efeito das novas assinaturas: marcações de uso único e recorrências gravadas para compostos, ou com o sufixo de descritor antigo, deixam de casar. A curadoria pode perguntar de novo, uma vez, por esses comandos.

01 · configure

Dashboard ou ambiente

Abra /dashboard → Router para escolher protocolo, URLs e headers. Em automação, use ROUTER_UPSTREAM_* ou ROUTER_BYOK_*. Precedência: dashboard/user-config.json → ambiente → defaults.

02 · escolha

Modelos reais no picker

IDs que não parecem Anthropic ganham um alias só para passar pelo filtro de /model. Antes da chamada, o router restaura o ID original.

gpt-4.1→anthropic-ccb-alias-gpt-4.1→gpt-4.1

03 · trabalhe

Tradução completa na rota OpenAI

Mensagens, imagens base64 suportadas, tools, tool results, JSON e stop reasons atravessam a ponte nos dois sentidos. No stream SSE, nomes de tool calls fragmentados são recompostos e o usage do chunk final separado chega no fechamento. Campo incompatível falha alto; nada some em silêncio.

04 · mapeie novo na v3.0.0

Mapeamento de modelo, só no BYOK

Opcional e vazio por padrão: regras origem → destino trocam o model enviado ao seu endpoint, em qualquer rota BYOK (always, fallback on-limit e cooldown). A ordem é previsível: ID exato, depois o ID sem data de snapshot, depois padrões com * (o mais específico vence). Sem regra, o modelo segue como veio; o caminho da assinatura nunca é alterado.

claude-sonnet-5-*→provedor.modelo-c

Para gateways que roteiam por outro campo, a injeção (desligada por padrão) grava o modelo resolvido num campo do corpo ou num header via template {model}. Regras e templates são editados em /dashboard → BYOK; regra inválida é recusada e falha alto, sem cair em silêncio para o plano B.

O router nasce desligado. Ativar BYOK ou um fallback pode gerar cobrança no endpoint escolhido. Para OpenAI, informe uma URL de contagem se o seu provedor oferecer essa operação; o protocolo não define um caminho padrão. Credenciais ficam fora do repositório.

Três coisas que o Claude Code nativo não faz

Tudo roda na sua máquina, com o embedding local baixado uma vez na instalação.

Brain KB: memória semântica por projeto

Três camadas locais: storage em SQLite pelo node:sqlite embutido (zero dependência nativa, com fallback para JSON), índice invertido com TF scoring e um grafo de citação de 6 tipos de aresta. Busca vetorial e busca por palavra-chave convivem.

  • Embedding padrão multilíngue (384 dim, 50 idiomas): prompt em PT recupera lição em EN
  • Providers alternativos: Ollama local ou Voyage AI, trocáveis na config
  • Escopo estável por projeto via .claude-boss-project ou CCB_PROJECT_ID
  • Backend opcional MCP Memory HTTP, com wizard, migração e auto-update local; destino remoto exige opt-in e nunca cai no fallback local

Curadoria anti context-bloat

Na 3.0.0 a curadoria casa por assinatura, redireciona e mede. No replay do histórico real (4.170 chamadas Bash, com o código do plugin), as negações do guard antigo caíram de 243 para 0.

  • Redirecionamento automático via updatedInput, inclusive dentro de compostos: allow em bypassPermissions, ask nos demais modos (o prompt mostra a reescrita). CCB_RAW=1 pede a saída crua
  • Só cura o que se repete: exploração (git log, grep, cat…) e código inline nunca viram script; no replay, cobranças do Stop caíram de 1.316 para 45 (−96,6%)
  • Exploração limitada sem Token Guard e em bypassPermissions: um comando de exploração isolado e sem pipe próprio (nunca tail -f/less) tem a saída limitada em streaming, até 80 linhas / 8000 caracteres, e a saída completa fica em .runtime/shaped. Com o Token Guard presente, o boss não interfere
  • Pipe sobre script curado é permitido e medido por script; o mesmo filtro repetido gera um pedido para embutir o filtro no script
  • Variante recorrente vira alias do script curado (EXTEND) em vez de um segundo script, e passa a ser redirecionada
  • Poda segura dos scripts que nunca rodaram na janela: botão Prune no dashboard ou a tool curation_prune_unused
  • Guarda de erro: nega só a repetição na mesma sessão e no mesmo diretório, sem edição desde a falha; no replay de 9.459 chamadas, bloqueios falsos caíram de 34 para 4
  • grep -r/rg/find amplos viram consulta estrutural ao grafo quando ele está pronto

Aprendizado leve, sem orquestrador próprio

Correções, falhas e padrões reusáveis viram entradas curadas do KB. O self-review lembra o que já deu errado naquele arquivo; a consolidação semanal funde lições quase-duplicadas somando recorrência.

  • Três perfis num eixo só: standard (silencioso, mas aprende), dev e free
  • Troca update-safe pelo comando /boss-profile ou pelo dashboard
  • Retrospectiva de falha e nudge de verificação quando o turno editou arquivo e nada rodou
  • Checklist de revisão recorrente oferecido ao /code-review nativo

E mais quatro peças, ligadas só quando você precisa

Nenhuma delas exige conta, chave ou serviço remoto para o funcionamento padrão.

  • Graph: exploração de repositório

    Sete tools graph_* (hubs por PageRank, busca com vizinhança, quem chama um símbolo) para entender um repo grande sem garimpar arquivo por arquivo. Cliente REST puro do Session Graph Engine: nenhum Java embarcado e, com o daemon offline, falham graciosamente.

  • Dashboard local sob demanda

    Abra com /dashboard: um hook responde, sem passar pelo modelo (0 turnos, US$ 0), sobe o painel se preciso, abre o navegador e mostra a URL. Servido em 127.0.0.1, com porta dinâmica e token gerado no boot. A aba Router configura upstream, BYOK, protocolos, URLs e headers; Brain KB, Hooks, Insights e Logs ficam no mesmo painel local. Novo na 3.0.0: o painel Curation & guards na Home separa a economia exata da estimada (sem linha de base, diz "sem base"), mostra o custo, uso por script, scripts que nunca rodaram (com botão Prune) e a latência por hook.

  • Doctor: diagnóstico zero-config

    Checa Node no PATH e versão, variáveis do plugin, fragmentação de data-dir, modelo de embedding, daemon e token, e quais eventos de hook a sua versão do Claude Code suporta. Vira advisory de uma linha no início da sessão só quando algo crítico falha.

  • BYOK e Model Router (opt-in)

    Nasce desativado. Você conecta custom upstream ou BYOK em Anthropic Messages ou OpenAI Chat Completions, separa as URLs por operação e escolhe modelos não Anthropic no picker por um alias reversível. No BYOK, um mapeamento opcional origem → destino ajusta o model enviado ao endpoint.

Um plugin de memória não pode custar caro para existir

A v2.28.0 juntou os detectores de cada evento num dispatcher in-process. Na 3.0.0, 13 hooks nem sobem processo: viram tools mcp_tool do brain-server e rodam no daemon HTTP compartilhado. A lógica de cada hook é a mesma; só o transporte muda.

  • Fail-open visível

    Uma exceção dentro da tool não bloqueia nada e devolve um systemMessage dizendo que o hook degradou. Cada hook tem um prazo interno abaixo do timeout do hooks.json. Ficam como command só os hooks que precisam funcionar com o daemon fora do ar, como o SessionStart.

  • Auditoria pré-release, tudo reproduzido antes de corrigir

    O moldador não embrulha mais comando com pipe próprio, com # de comentário ou de follow/interativo (tail -f, less, watch), e faz streaming: a cabeça sai na hora. Um job que nunca termina na lane pesada não trava mais os hooks pesados de todas as sessões: depois de 3 prazos seguidos sem progresso, o worker é reciclado. E o desligamento do worker de embedding no meio do init não derruba mais o daemon.

  • Cada sessão com a sua raiz

    O Claude Code entregava ${CLAUDE_PROJECT_DIR} vazio ao mcp_tool. Agora o SessionStart grava session_id → raiz e o daemon resolve por ela; as métricas usam a raiz da sessão, não o cwd do shell. O Stop de uma sessão não mostra mais commits feitos em outra.

  • Reconexão e upgrade sem ficar preso

    Sessão MCP desconhecida responde 404 e o cliente reinicializa sozinho em vez de ficar failed (G16). Uma instalação mais nova substitui o daemon antigo, nunca faz downgrade (G13), e um daemon servindo outro dataDir não é compartilhado (G15).

  • Auto-update com fronteira explícita

    No SessionStart, o dispatcher existente consulta atualizações do MCP Memory no máximo uma vez a cada 24 horas, sem hook novo. Um serverUrl remoto só participa com opt-in explícito e nunca aciona o fallback local. Se a versão nova não sobe, o Boss restaura a anterior e só confirma o rollback depois que /health.version devolve exatamente essa versão.

  • Nenhum console piscando no Windows

    Todo processo filho que o plugin sobe em runtime passa windowsHide: true: com subagentes e sessões paralelas, nenhuma janela cmd abre nem rouba o foco. A regra ESLint local/require-windows-hide, que não pode ser desligada inline em scripts/ e servers/, impede a regressão. A porta padrão do daemon passou de 58217 para 38217, fora da faixa que o Windows reserva.

O pré-requisito número um é Node.js 22.13+ no PATH do sistema: o Claude Code dispara hooks e MCP com o node do PATH, não com o Node embutido no Desktop. No Windows, feche o Desktop por completo depois de instalar e reabra, para herdar o PATH.
