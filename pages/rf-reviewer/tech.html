O motor determinístico por baixo

Para quem quer saber como funciona por baixo: o MCP rf-engine com 9 tools, o daemon HTTP único, os hooks de enforcement e o fluxo completo de revisão. Plugin irmão do claude-code-boss no mesmo marketplace — com escopo segregado (conversão/anotação de Excel vs. conhecimento de sessão).

Arquitetura daemon HTTP único

O rf-engine (Python + openpyxl) é servido por Streamable HTTP a partir de um daemon único na porta 127.0.0.1:19847 — as sessões conectam como clientes finos, sem 1 processo por sessão. O .mcp.json usa type:http e só aponta a URL do daemon.

sessão 1▸ sessão 2▸ sessão N▸ daemon rf-engine :19847▸ 1 Python · openpyxl

Garantia do daemon

  • SessionStart (servers/rf-engine/plugin_daemon.py): sobe/garante o daemon HTTP único no início da sessão (idempotente, porta 127.0.0.1:19847).
  • Servidor HTTP é stdlib — a única dependência Python é openpyxl.
  • Requisitos: Python 3.11+ no PATH + openpyxl; MCP HTTP (rollback para a versão stdio anterior: /plugin install rf-reviewer@rf-v0.1.1).

MCP rf-engine 9 tools

O motor é determinístico: os 9 tools cobrem o ciclo completo, do perfil à prova de preservação.

ToolO que faz
rf_perfis_listarLista os perfis de colunas disponíveis
rf_perfil_definirEscolhe/define o perfil para a revisão
rf_prepExtrai a planilha e prepara as colunas de análise
rf_brain_buscarBusca na memória do projeto o contexto relevante
rf_brain_enriquecerEnriquece a análise com o que a memória sabe
rf_applyInjeta a análise de volta na MESMA planilha (colunas anexadas)
rf_validarValida a revisão antes de gravar
rf_verificar_preservacaoProva que o original ficou intacto (comparação célula a célula)
rf_statusEstado atual da revisão em andamento
Divisão de trabalho: o motor faz a mecânica (extrair, preparar, injetar, validar, versionar); o agente faz só o julgamento (preencher a análise cruzando com a memória do projeto, via rf_brain_buscar/rf_brain_enriquecer).

Hooks de enforcement determinísticos

Três camadas garantem que o trabalho acontece pelo motor e não "na mão".

SessionStart

plugin_daemon.py

Sobe/garante o daemon HTTP único do rf-engine (idempotente). É o que permite o transporte HTTP com daemon compartilhado.

UserPromptSubmit

rf-remind.js

Quando o pedido é de RF em planilha, injeta no contexto o fluxo do RF Reviewer (rf_prep → … → rf_apply) — lembra sempre, sem depender do modelo "lembrar".

PreToolUse/Bash

rf-guard.js

Se o agente tentar mexer no .xlsx na mão (openpyxl/pandas gravando workbook), pede confirmação e redireciona para rf_apply. Não bloqueia leitura nem a CLI legítima do motor.

Fluxo de revisão guiado pela skill revisar-rf

rf_perfis_listar▸ rf_prep▸ agente preenche▸ rf_validar▸ rf_apply▸ rf_verificar_preservacao

O que entrega

  • A mesma planilha do cliente + as colunas de análise anexadas (perfil escolhido).
  • Versionada: _revisado_vN.xlsx — o original fica 100% intacto (prova por comparação célula a célula).
  • Agente + memória: a revisão cruza cada requisito com o servidor de conhecimento do projeto (project_id da sua memória).

Escopo importante

serve

Arquivos tabulares

.xlsx (núcleo) e .csv. Qualquer assunto via perfil de colunas trocável.

não serve

Documentos

.pdf / .docx / .pptx seguem outro fluxo (análise de documento) — injetar coluna só faz sentido em tabela.
